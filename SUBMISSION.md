# Compass — Judging & Architectural Summary

Compass is an intelligent, multi-domain personal copilot and autonomous planning agent designed for builders, researchers, and students juggling hackathons, academic coursework, and complex software projects.

Built with **Nebius Token Factory**, **NVIDIA Nemotron LLMs**, **Neon Serverless PostgreSQL (pgvector)**, and **Tavily Web Intelligence**.

## 2. Nebius & NVIDIA Model Routing Table

Compass routes tasks dynamically across specialized Nebius models based on required latency, context depth, and cost efficiency:

| Role | Provider / Platform | Model Identifier | Context / Dim | Rationale |
| :--- | :--- | :--- | :--- | :--- |
| **Fast Router & Structured Tools** | Nebius Token Factory | `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B` | 32K context | Sub-400ms TTFT, native tool calling, lowest token cost. |
| **High-Precision Reasoning & Agent**| Nebius Token Factory | `nvidia/Nemotron-4-340B-Instruct` / Super | 32K context | Complex multi-step reasoning, plan synthesis, and dispute resolution. |
| **Semantic Embeddings** | Nebius Token Factory | `Qwen/Qwen3-Embedding-8B` | 768-dim (Matryoshka) | Matryoshka dimension truncation from 4096 down to 768 dims to respect PostgreSQL's 2,000-dimension HNSW index ceiling. |

## 4. Local Setup & Testing

### Prerequisites
- Python 3.11+
- Node.js 18+ (for frontend)
- PostgreSQL with `pgvector` extension

### Backend Setup
```bash
git clone https://github.com/Ratnesh-101/compass.git
cd compass
python -m venv .venv
source .venv/bin/activate  # Or .venv\Scripts\activate on Windows
pip install -r backend/requirements.txt -r requirements-test.txt

# Run full test suite
python -m pytest tests/ -v
```

### Running the Live Proof Demonstration
```bash
# Executes 3 real runs: VERIFIED, CHANGED, and Live Nebius x NVIDIA query
python scripts/demo_two_runs.py
```

### Frontend Setup
```bash
cd frontend
npm install
npm run dev
```

## 5. Known Limitations & Edge Cases

1. **Free Tier Cold Starts**: The backend is hosted on Render's free container tier, which spins down after 15 minutes of inactivity. Initial wake-up requests may take 45–60 seconds.
2. **Third-Party Calendar Sync**: Google Calendar sync requires real Google OAuth credentials (`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`). In unconfigured demo mode, a simulated calendar interface is provided with full local task scheduling functionality.
3. **Multi-Worker Session Invalidation**: The current session store is memory-backed (`dict[str, dict]`). Under multi-worker deployments, a shared Redis or Neon database session table is recommended for session sharing across worker processes.
